## Что это

Небольшой бот, которого я собрал для приёма заявок computer-мастера. Клиент открывает бота, выбирает проблему или услугу, оставляет телефон — заявка приходит мастеру в личку.

Задача была не сделать «CRM с личным кабинетом», а закрыть простой сценарий: человеку нужно срочно починить компьютер, он не хочет звонить и объяснять одно и то же. Бот собирает вводные и передаёт их мастеру.

---

## Что умеет

- Показывает прайс-лист услуг.
- Принимает **экстренную заявку**: «не включается», «синий экран», «вирусы», «нет интернета».
- Принимает **запись на услугу**: выбор услуги → дата → время → телефон.
- Отправляет заявку в чат мастера с именем, username, ID и составом запроса.
- Даёт мастеру кнопку «Написать клиенту» (`tg://user?id=...`).
- Не теряет состояние между кнопками: выбор услуги, дата и время хранятся в сессии.

## Запуск

Нужен [Bun](https://bun.com) и токен от [@BotFather](https://t.me/BotFather).

```bash
bun install
cp .env.example .env
```

В `.env`:

```env
BOT_TOKEN=123456:AA...
MASTER_CHAT_ID=123456789
```

`MASTER_CHAT_ID` — ID чата, куда приходят заявки. Свой ID можно узнать у `@userinfobot`.

```bash
bun run start
```

Бот работает через long polling, поэтому локально не нужен HTTPS и ngrok.

Для разработки:

```bash
bun run dev
```

## Как это работает

- `getUpdates` с `timeout: 30` — обычный long polling.
- Состояние диалога лежит в `Map<chatId, State>`: шаг, выбранные пункты, дата, время.
- Клавиатуры — inline, все переходы на `callback_data`.
- Телефон запрашивается через `request_contact`, а не вводом текста.
- Сообщения отправляются с `parse_mode: "HTML"`; пользовательский ввод экранируется.
- Заявка мастеру уходит отдельным сообщением, после чего состояние клиента сбрасывается.

Состояние в памяти — сознательное упрощение. Для одного мастера и десятка заявок в день этого достаточно. При перезапуске активные диалоги сбросятся.

## Ограничения

- Нет базы данных: заявки не сохраняются, только отправляются в Telegram.
- Нет админки, статусов заявок и истории.
- Нет оплаты и интеграции с календарём.
- `MASTER_CHAT_ID` один; несколько мастеров не поддерживаются.
- Токен и ID чата — только через переменные окружения, в коде их нет.
